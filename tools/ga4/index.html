One per line, parameters after a colon: add_to_cart: currency, value, items. A column or rows pasted from a sheet work too.

        Where the rules come from. Google’s event naming rules (start with a letter; only letters, numbers and underscores; case-sensitive; reserved names and parameter prefixes), its collection limits (40-character event and parameter names, 25 parameters per event, anything over a limit isn’t logged), the Measurement Protocol reference (reserved event names, app-only events), the app SDK’s event naming rules (reserved google_, ga_ and firebase_ prefixes; invalid events are dropped) and the list of recommended events.

        Web and app streams differ. screen_view, in_app_purchase and ad_impression are only accepted by app streams. page_view, scroll, click, form_start, form_submit, file_download, the video events and view_search_results are collected automatically on web, so they’re a warning there, not an error. App streams also allow at most 500 different event names per user; web streams have no such cap.

        Some checks are estimates. Google states the google_, ga_ and firebase_ event prefixes for app streams; we treat them as reserved on web too. The near-miss suggestions come from our own list of common alternative names (purchase_complete, initiate_checkout, view_product and the like), not from Google.
